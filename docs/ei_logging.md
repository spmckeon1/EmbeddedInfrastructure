# Logging

## Design Philosophy

- The Logging subsystem is responsible for recording events.
- The application owns the content and meaning of each log message.
- Logging owns all infrastructure metadata, formatting, routing, buffering, and delivery.
- This separation keeps application logic independent of logging implementation details.

## Purpose

The Logging subsystem provides a centralized mechanism for recording events generated by the application and infrastructure. It is responsible for enriching application messages with infrastructure metadata and delivering them to the configured destination.

## Responsibilities

- Receive application log messages.
- Add timestamps.
- Add component information.
- Add sequence numbers.
- Format serial output.
- Format MQTT JSON output.
- Route log messages to the active destination.
- Buffer messages while MQTT is unavailable.

## Non-Responsibilities

- Creating application messages.
- Interpreting application data.
- Managing network connections.
- Synchronizing time.
- Persisting application configuration.

## Ownership

### Logging owns

- Active log destination (`_dest`)
- Sequence number generation
- RAM log buffer
- Log routing policy
- Log formatting
- Log message delivery

### Other subsystems own

- Time synchronization
- MQTT connection state
- Storage
- Application configuration

## Public Interface

### Logging.msg

#### Purpose

The application constructs the complete human-readable message. The Logging subsystem enriches that message with infrastructure metadata (timestamp, sequence number, component, etc.) but never changes its meaning.

#### Syntax

void logging.msg(String event, String functionName, int lineNo)

#### Parameters

event - Human-readable description of the event.
functionName - Usually supplied using FN.
lineNo - The code line desired to be shown in the log message.  This is usually supplied using LN.

#### Responsibilities

- Adds infrastructure metadata.
- Formats the message for each output.
- Routes the message to the active destination.
- Never modifies the application message.

#### Caller Responsibilities

- Construct the complete human-readable message.
- Supply FN and LN.

### logging.setDestination()

#### Purpose

Changes the active log destination.

#### Syntax

void setDestination(LogDestination destination)

#### Parameters

##### Log Destinations

###### RamBuffer

The default destination during startup and whenever MQTT is unavailable. Messages are retained in memory until they can be forwarded.

###### MqttServer

The normal operating destination after MQTT has connected successfully. Messages are published immediately.

#### Typical Usage

- During startup, Logging defaults to RamBuffer.
- When MQTT becomes available:
    logging.setDestination(LogDestination::MqttServer);
- If MQTT is lost:
    logging.setDestination(LogDestination::RamBuffer);

## Startup Sequence

- Logging starts.
- Destination defaults to RamBuffer.
- Messages are written to the RAM buffer.
- MQTT becomes available.
- Destination changes to MqttServer.
- Buffered messages are flushed to MQTT 1 msg at time.
- New messages go directly to MQTT.
- MQTT disconnects, messages are routed to the RamBuffer

#### Notes

The Logging subsystem owns the destination. Callers request a change; they never manipulate internal state directly.

## Log Flow

Application
      │
      ▼
logging.msg()
      │
      ├── formatSerial()
      ├── formatJson()
      ▼
Dispatch to Destination
      │
      ▼
RamBuffer   or   MQTT

## Message Format

DATE/TIME, CODE LINE NUMBER, CODE FUNCTION, MESSAGE

Example:
2026-07-19 06:14:37.348-CDT, Line#:651, FROM: turnShOff: Turning Night shade off.

## Routing

The Logging subsystem routes every log message to the currently configured destination.

The active destination is owned by the Logging subsystem and is changed through `logging.setDestination()`. Logging does not determine when the destination should change; other subsystems are responsible for making that decision.

Once the destination has been set, Logging is responsible for delivering all messages to that destination.
