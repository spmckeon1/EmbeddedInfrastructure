# EmbeddedInfrastructure Organization

## Purpose

Describes how the EmbeddedInfrastructure architecture is implemented within the
source tree.

Architecture defines responsibilities.

Organization defines where those responsibilities are implemented.

---

## Evolution

This document describes the current organization of the
EmbeddedInfrastructure source tree.

The organization is expected to evolve as the framework grows.
Changes should preserve the architectural principles defined in
Architecture.md while improving cohesion, clarity, and maintainability.

New modules should be introduced when they represent a distinct
responsibility, not simply to reduce file size or code volume.

---
## Organization Principles

1. Every function belongs to exactly one module.

2. Place functionality according to responsibility, not convenience.

3. Every module should have a clear, cohesive purpose.

4. Prefer placing new functionality into an existing module whose
   responsibility naturally includes it.

5. If functionality does not naturally belong in an existing module,
   consider creating a new module rather than expanding an unrelated one.

6. ei_utilities is the module of last resort and should remain as
   small as practical.

7. File names describe the implementation organization, not the
   architecture.
   
8. When in doubt, ask "Who owns this responsibility?" rather than "Where is there room for this code?"

## Module Organization

### ei_framework

#### Purpose

Provides the common infrastructure that supports every EmbeddedInfrastructure application. It manages the framework lifecycle and coordinates the initialization and operation of framework services.

#### Responsible For

- Framework startup
- Framework shutdown
- Initialization sequencing
- Framework lifecycle management
- Shared infrastructure services

#### Not Responsible For

- Application logic
- Device behavior
- Configuration persistence
- Logging implementation

### ei_configuration

#### Purpose

Provides persistent configuration services for EmbeddedInfrastructure. It manages the storage, retrieval, validation, and migration of configuration data used by infrastructure components.

#### Responsible For

- Configuration storage
- Preference storage
- Configuration validation
- Serialization
- Configuration version management

#### Not Responsible For

- Runtime state
- Application data
- Device status

### ei_logging

#### Purpose

Provides a consistent logging service for EmbeddedInfrastructure. It manages the creation, formatting, routing, and delivery of diagnostic information generated by framework components.

#### Responsible For

- Log generation
- Log formatting
- Log routing
- Log destinations
- Log filtering

#### Not Responsible For

- Dashboard presentation
- Log analysis
- Event visualization

### ei_time

#### Purpose

Provides system time services used throughout EmbeddedInfrastructure. It supplies a consistent interface for obtaining, synchronizing, formatting, and manipulating time.

#### Responsible For

- Time synchronization
- Time formatting
- UTC and local time conversion
- Uptime
- Time utilities

#### Not Responsible For

- Scheduling
- Timers
- Application timing policy

### ei_system

#### Purpose

Provides access to platform and operating system services that are specific to the target hardware. It isolates hardware-specific functionality behind a consistent framework interface.

#### Responsible For

- System restart
- Heap information
- Chip information
- Reset information
- Diagnostics
- Platform services

#### Not Responsible For

- Configuration
- Logging
- Device drivers

### ei_utilities

#### Purpose

Provides general-purpose helper functionality that has no natural home within another infrastructure module.

This module exists to support the framework—not to become a repository for unrelated code.

#### Responsible For

- General-purpose helper functions
- Small reusable algorithms
- Common utility routines

#### Not Responsible For

- Functionality that naturally belongs to another module
- Framework services
- Device-specific behavior
